03 — Solution

One platform, six roles,
each with real work to do.

Role 01

🐾 Pet Owner

Pet profiles and medical history, veterinary and training bookings, marketplace, community posts, and lost-pet reports.

Role 02

🩺 Veterinarian

Clinic presence — licence, fees, specialties, hours — with an appointment queue, patient records scoped to pets actually seen, and staff seats.

Role 03

🎓 Trainer

Independent practice with certifications, methodology, session pricing and service area, on a tracker shaped for training rather than clinical work.

Role 04

🏪 Vendor — Pet Shop

Storefront with stock control, bulk catalogue import, order management, reviews with replies, banner campaigns and revenue analytics.

Role 05 · New in Phase 2

🗂️ Clinic Assistant

A delegated reception seat created by a vet. Handles appointments without reaching clinical records, can be revoked at any time, and every action is audit-logged.

Role 06

🛡️ Administrator

Credential verification, moderation with appeals, feature flags, commission settings, database health, a full audit log, and an AI analytics console.

Authorisation, not just authentication

RBAC is enforced at the route layer and again inside every controller, with ownership conditions written into the SQL WHERE clause — so a request for another user's record returns nothing, rather than relying on a check that could be skipped.

04 — Technology stack

Every choice had to survive a
student budget and a real deployment.

Frontend

React 19 · Vite 8 · Tailwind

Instant rebuilds during a 12-week cycle, and one design system reused across six dashboards.

Backend

Node.js · Express 4

One language across the stack, and a middleware model that let the security layer be inserted without touching controllers.

Database

PostgreSQL on Supabase

Relational integrity for bookings and orders, with a managed host that removes server administration from scope.

Auth

JWT · bcrypt

Stateless tokens survive serverless cold starts, where a session store would not.

AI

AI SDK · Zod · Groq / Ollama

Free and self-hosted inference behind one environment variable — no paid subscription anywhere.

Integrations

Cloudinary · Leaflet · Paymob · Twilio · Tesseract

Local OCR replaces a paid identity service; Overpass supplies real nearby shops at no cost.

Testing

Node · Axios · custom harnesses

Suites that run against a live server, so they verify deployed behaviour rather than mocks.

Deployment

Vercel · GitHub

Push-to-deploy from the monorepo, with API and frontend released independently.

The constraint behind it

Nothing in this stack carries a licence fee. Every paid dependency was replaced with a free or self-hosted equivalent before it entered the build.

05 — Delivered · agentic AI

VetAI does the task,
it does not just describe it.

Ten typed tools — click one
Design principle

Safety runs before intelligence

Emergency and toxicity detection is deterministic and executes before the model is called. A dog that has eaten chocolate triggers the emergency path from a keyword rule, in English and Arabic alike — so a slow, throttled or misbehaving model can never suppress a safety response.

Grounding

Retrieval before generation

A curated veterinary knowledge base is searched first, weighting rare terms above common ones and matching on species — so a question about cats never returns guidance for dogs. If the model is unavailable, the retrieval answer is served on its own rather than failing silently.

Interface

The conversation drives the app

The assistant returns structured blocks the interface renders as real controls — a slot picker, appointment actions, calendar links, navigation cards. Every link it emits is validated against the real route table, so it cannot send a user to a page that does not exist.

Why this is the flagship

A chatbot that answers questions is a feature. An assistant that books the appointment — and refuses to when the case is an emergency — is a system.

05 — Delivered · administration

The platform can be operated,
not only demonstrated.

Control

🎛️ Feature flags

Any major area — vets, marketplace, subscriptions, hosting, community, lost & found, adoption — can be switched to "coming soon" without a deployment. This is how the platform soft-launches one region at a time.

Trust

📄 Credential verification

Professionals upload licence documents, read with local OCR, and an administrator approves or rejects with reviewer notes before the profile becomes publicly visible.

Accountability

🧾 Audit log

Every privileged action — role change, ban, approval, moderation decision, commission edit — is written to an append-only log with the acting administrator recorded.

Moderation

⚖️ Queue with appeals

AI auto-moderation soft-deletes violating posts; the author can appeal, and the appeal lands in the administrator queue for restore or permanent deletion.

Operations

🩻 Database health

Live metrics, backup triggers and index optimisation from the admin console, so the team can diagnose the production database without a separate tool.

Insight

🤖 AI analytics console

Natural-language queries over platform data, with the model's output constrained to read-only reporting — agentic AI applied to operations rather than to end users.

A note on the AI console

The security classifier behind it is deliberately clamped: a SQL-injection signature can never be downgraded below CRITICAL, whatever the model returns. Model judgement enriches a decision, never makes it.

07 — Security · methodology

The scanners came back clean.
Manual testing did not.

Three passes

Pass 01 · Black-box

The live application only — no source, no credentials beyond a normal account. Enumeration, authorisation probing, header and CORS inspection, injection attempts against every reachable endpoint.

Pass 02 · Grey-box

Repeated with repository and schema access. This is where the credential exposure and the unscoped controller queries surfaced — classes of flaw that are invisible from outside.

Pass 03 · AI-specific

VetAI tested separately for prompt injection, system-prompt disclosure, tool enumeration, and personal data leaking through raw response blocks.

Confirmed findings by severity — eight issues, all reproducible
Toolchain — what it caught
Burp Suite, curl, ffufFound the access-control and IDOR flaws
jwt_toolToken structure and signature testing
TruffleHogFound the committed credentials
nuclei, GitleaksReported nothing — missed every confirmed finding
npm auditDependency advisories — 32 open at the start

Carried out on Kali Linux, with custom Python scripts for the repeatable probes.

The result that matters

Not one confirmed vulnerability was reported by an automated scanner. Every finding below came from a person testing by hand.

08 — Engineering decisions

Six constraints that shaped the build.

A pool per request exhausts the database

On serverless every request runs in its own short-lived instance, so a conventional pool multiplies connections until Supabase refuses them. Pooling is tuned to one connection per instance in production, five locally.

Nothing lives long enough to hold a socket

Real-time messaging uses Socket.IO where a persistent process exists, and falls back to short-interval polling in production. Messaging behaves identically either way.

No budget for paid model inference

The AI provider is swappable through one environment variable — Groq in production, local Ollama offline, a deterministic mock in CI. All three speak the same protocol, so application code never changes.

Identity checks cost money per document

Licence documents are read with Tesseract.js running locally. No third-party verification service, no per-check fee, and no identity document leaves our infrastructure.

A model cannot be trusted with safety

Emergency detection, toxicity rules and the final screening pass are deterministic and independent of the model, and the security classifier's output is clamped so a critical finding can never be downgraded.

Ten people committing to a public repository

A pre-commit hook rejects any staged file containing a database URL with an inline password or an API-key-shaped string — because the exposure we found had already happened once.

The pattern

Every decision above trades convenience for something we could still defend on a serverless deployment, with no budget, and a public repository.

08 — Roadmap

What we would do next, and
what we would not claim yet.

Product — next build cycle
  • Dedicated shop storefronts with owner-authored profiles and stable links shipped since
  • Trainer programmes — multi-session courses, group classes with rosters, per-dog progress shipped since
  • Clinic wallet with an earnings ledger and withdrawals shipped since
  • Loyalty and rewards for repeat owners
  • Continued reduction of AI inference cost per message
Security — carried forward from the assessment
  • Rotate the exposed database credential and purge it from git history done
  • Move the application off the database super-user onto a scoped, least-privilege role
  • Enable dependency scanning in CI, so advisories surface on every push
  • Re-test the AI assistant after each tool is added, since every new tool widens the attack surface
What Phase 2 established

A working platform is not the same as a trustworthy one. The most useful outcome of this phase was not a feature — it was discovering that a codebase which passes every automated scan can still expose a super-user credential, leak another owner's personal data through a predictable identifier, and serve an unenforced content security policy. Those were found by hand, by a member of this team, and closed before anyone outside it saw the system.

Next milestone

Soft-launch one governorate behind feature flags, with the credential rotation and the scoped database role completed first.
